# v1 Restore 选择原因：诊断结果

## 范围与结论

检查点为 `runs/v1/model.zip`，SHA256 为 `43c39ab96a68d8e2bd91900835cfa046d2ce98268d8dc4c5a9033d71c1e9521b`。本次没有训练、改动模型、环境奖励或策略代码。

运行 50/100 步 × B_line/Meander/Sleep × 确定性/随机采样，每组 30 回合（种子 153–182），共 360 回合、27,000 步。不同动作可能改变模拟器随机数消耗，因此相同种子不等于后续攻击轨迹完全相同。结果是诊断实验，不替代之前每组 1,000 回合的正式评估。

已确认的主要机制是：**不可处置初始落点的告警影响子网与其他主机的表示；在不得选择该落点时，模型转而恢复同子网的无告警主机。动作头同时保持略高于 Remove 的 Restore 偏好，确定性最大值选择将这一偏好表现为始终恢复。** B_line 的很多恢复则确实发生在再次入侵后，不能把所有重复恢复归为同一种原因。

## 轨迹证据

确定性评估中：

| 对手 / 长度 | Restore 次数 | 目标四维观测全零 | 恢复前目标无红方会话 | 连续两步恢复同一全零观测主机 |
|---|---:|---:|---:|---:|
| B_line / 50 | 735 | 0 | 30 | 0 |
| B_line / 100 | 1,475 | 0 | 30 | 0 |
| Meander / 50 | 1,292 | 553（42.8%） | 673（52.1%） | 143 |
| Meander / 100 | 2,792 | 1,313（47.0%） | 1,433（51.3%） | 349 |

Meander 的上述 553/1,313 次全零目标恢复，全部发生在**只有 User0 的输入特征非零**的状态。全零表示 BlueTable 没有目标告警，不单独等价于主机安全；这里另外读取模拟器会话作事后核验，未将隐藏会话状态传给模型。

B_line / 50 的 735 次恢复中，680 次目标显示 Exploit/User，55 次显示 Scan/No；705 次恢复前目标存在红方会话。种子 153 的前几步表现为：第 3 步扫描后提前恢复，第 4 步已出现利用和红方会话，再恢复；第 5 步 Monitor；第 6 步再被利用后恢复。因而简单冷却可能同时阻碍实际处置。

## 为什么选中了 User1 + Restore

实际样本：Meander、50 步、种子 153、第 9 步。

- 仅 User0 的特征为 `[1,1,0,1]`（Exploit/User）；User1–User4 等其他主机都是 `[0,0,0,0]`。
- User0 是初始攻击落点，动作掩码禁止对其处置，但它仍参与图消息传递和子网平均池化。
- 子网概率：Enterprise 13.02%、Operational 13.02%、User **73.33%**、全局分支 0.64%。
- User 子网内可选的四台主机各占 25%，具有相同表示。四个 Restore 组合并列最大，扁平 argmax 取索引最靠前的 User1。
- 对 User1 的条件动作概率：Analyse **0.73%**、Remove **43.01%**、Restore **56.26%**。
- User1+Restore 联合概率为 **10.31%**，User1+Remove 为 7.88%，Monitor 为 0.60%。因此当前解码确实按照联合分布正确选择了 Restore，不是概率索引错误。

在这些确定性 Restore 样本中，条件 Restore 概率约为 56.26%–56.59%，Remove 约为 42.68%–43.01%。目标从扫描、利用到全零时，这一偏好变化很小。该证据说明动作区分能力不足，但不能仅凭此断言其训练原因是熵系数、步数或梯度问题。

## 输入敏感性验证

保持上述模型参数不变，对同一输入进行离线消融：

| 输入修改 | 选出的动作 |
|---|---|
| 原始输入 | Restore User1 |
| 仅清除 User0 的观测特征 | Monitor |
| 仅清除已全零的 User1 特征 | Restore User1 |
| 仅隔离 User0 图连接，保留自环 | Monitor |
| 仅从子网池化移除 User0，保留消息传播 | Restore Defender |
| 同时隔离 User0 图连接并排除其池化 | Monitor |

当前邻接矩阵的真实主机部分为全 1：13 台主机互相连通，包含自环。原因是环境适配器仅根据声明的出站 NACL 生成粗粒度边，而 Scenario2 的出站配置均为 all。它没有表达完整的入站限制和路由关系。这样 User0 的信息可经 max 聚合传播到所有主机；只修改子网池化不能消除该传播路径。

这些消融验证了**该样本的决策依赖路径**，不是修改后环境性能实验。不能由此声称“屏蔽 User0 就一定提高回报”；也未证明全连接图是所有性能问题的唯一原因。

## 随机采样是否能解决

| 长度 / 对手 | 联合 argmax 回报 | 随机采样回报 |
|---|---:|---:|
| 50 / B_line | -26.36 | -51.66 |
| 50 / Meander | -44.69 | -50.57 |
| 50 / Sleep | 0 | -21.23 |
| 100 / B_line | -52.95 | -108.70 |
| 100 / Meander | -96.56 | -128.97 |
| 100 / Sleep | 0 | -41.20 |

随机采样会执行 Remove，但没有改善这批诊断种子的均值。以 50 步 Meander 为例，动作成本从 -43.07 降至 -27.43，但状态奖励从 -1.62 恶化到 -23.14，最终回报更差。仅减少 Restore 次数不是足够的优化目标。

Sleep 下确定性策略虽全部选择 Monitor，但 Restore 的**动作边际概率仍有约 42.04%**，只是分散在多台主机上，每个组合的概率小于 Monitor。因此随机采样仍会频繁恢复无告警主机。这说明当前分布本身并未学会在全零观测时基本放弃恢复，不能只归因于确定性解码。

## 下一步优先级

应先对**图连接构造、不可处置节点信息的传播，以及子网/主机的可处置性区分**做最小消融。保留合法动作和原始奖励，不直接禁止 Restore。再检查动作头能否区分扫描、用户访问、特权访问和无告警状态。历史特征仍可作为后续对照，但现有证据不支持优先把问题全部归因于缺少历史。
